# Задания по алгоритмам и структурам данных, технологиям программирования на C++

## Структура папок
### Алгоритмы и структуры данных (aads)
Реализация собственных структур данных.

  - `S1`: реализация шаблона класса двунаправленного списка и соответствующих итераторов. Демонстрационное приложение: обработка последовательностей чисел, прочитанных со стандартного ввода с использованием списков;
  - `S2`: реализация интерфейсов шаблонов классов стека и очереди на основе динамического массива. Демонстрационное приложение: разбор арифметических выражений, преобразование инфиксной формы записи в постфиксную с использованием стека и очереди.
  - `S4`: реализация шаблона класса бинарного дерева поиска (2-3 дерева) и соответствующих итераторов. Демонстрационное приложение: чтение словарей заданного формата из файла, пользовательские консольные команды для работы со словарями.
  - `S5`: реализация инфиксных обходов дерева, обхода дерева в ширину с использованием шаблонов классов стека и очереди (тяжелые итераторы). Демонстрационное приложение: чтение дерева из файла и обход в соответствии с заданной стратегией.
  - `S7`: реализация шаблона класса хэш-таблицы (разрешение коллизий методом Робину Гуда) и соответствующих итераторов. Демонстрационное приложение: чтение графов заданного формата из файла, пользовательские консольные команды для работы с графами.

### Технологии программирования (tp)
Работа с STL: стандартные контейнеры, алгоритмы, функторы.

- `T2`: реализация операторов ввода/вывода для собственной структуры данных, сортировка и форматированный вывод введенных структур.
- `T3`: реализация операторов ввода/вывода для геометрических фигур, обработка пользовательских консольных команд для фигур.

## Сборка работ

Для сборки и запуска работ присутствует Makefile для
[GNU Make](https://www.gnu.org/software/make/). Все работы
автоматически обнаруживаются и могут быть построены с использованием нескольких целей.

Идентификатором каждой работы является строка
`subject(aap | aads | tp)/labnumber`, на которую далее ссылаются с помощью `labid`.

Все исходные тексты в каждой работе идентифицируются по расширению
"cpp". Обнаруженные исходные тексты делятся на группы:

* Исходные тексты работы: все файлы, имена которых _не_ начинаются с
  "test-".

* Исходные тексты тестов: все файлы, исключая файл "main.cpp".

Общие файлы для нескольких работ размещены в подкаталоге
"common". Они будут автоматически добавлены при сборке
работы. Внутри каталога "common" допустимо создавать подкаталоги для
организации файлов. Файлы из этого каталога включены с
помощью директивы `#include <...>` с угловыми скобками.

Поддерживаемые цели:

* `build-labid`: построение лабораторной работы, например

        $ make build-aap/P1

* `run-labid`: запуск построенной программы, например

        $ make run-aap/P1

    Для передачи дополнительных параметров используется переменная
    `ARGS` (при помощи GNU Make):

        $ make run-aads/S1 ARGS="1 ascending"

    или (c использованием Bourne Shell):

        $ ARGS="1 ascending" make run-aads/S1

    или (Bourne Shell, с сохранением в окружении процесса):

        $ export ARGS="1 ascending"
        $ make run-aads/S1

* `test-labid`: сборка и запуск модульных тестов работы:

        $ make test-aads/S3

    Переменная `TEST_ARGS` используется для передачи параметров тестам
    аналогично `ARGS`.

* `labs`: список всех лабораторных в проекте.

* `format-labid`: форматирование лабораторной программы с помощью clang-format:
  
        $ make format-tp/T2

  Доступные дополнительные параметры, передаваемые с помощью переменной `ARGS`:
  
  `--check`: отображение частей кода, отформатированных не по CG,
  
  `--fix`: исправление кода, в соответствии с CG,
  
  `--info`: вывод вспомогательной информации о доступных параметрах, работе с пунктами CG

  По умолчанию (без передачи параметров) выполняется режим `--check`.

* `tidy-labid`: статический анализ кода с помощью clang-tidy:
  
        $ make tidy-tp/T2

  Доступные дополнительные параметры, передаваемые с помощью переменной `ARGS`:
  
  `--check`: отображение частей кода, отформатированных не по CG,
  
  `--info`: вывод вспомогательной информации о доступных параметрах, работе с пунктами CG.

  По умолчанию (без передачи параметров) выполняется режим `--check`.
  

Дополнительной возможностью является запуск динамического анализатора
[Valgrind](http://valgrind.org) для запускаемых программ. Для этого
необходимо указать в переменной `VALGRIND` параметры анализатора так,
как это делается для `ARGS`/`TEST_ARGS`.

## Установка и использование автоматических средств форматирования кода средствами clang-format и clang-tidy
В стандартных репозиториях Debian/Ubuntu последняя версия clang-format и других инструментов clang - 14. Чтобы установить более новую версию, нужно использовать скрипт с официального сайта llvm:
```
wget -O – https://apt.llvm.org/llvm.sh
chmod +x llvm.sh
sudo ./llvm.sh 20
sudo apt install clang-format-20
sudo apt install clang-tidy-20
```
## Настройка clang-format и clang-tidy в VS Code
VS Code имеет встроенную поддержку clang-format, по умолчанию устанавливается clang-format style=file, что значит, что clang-format файл с ищется в текущей директории. Если файл не найден, используется стиль, установленный по умолчанию в `C_Cpp.clang_format_fallbackStyle`. Можно настроить исправление при сохранении, копировании и другие опции.

Расширение C/C++ от Microsoft имеет поддержку clang-tidy. Настройки указываются в `C_Cpp > Code Analysis > Clang Tidy:Config`. Если поле пусто, clang-tidy будет искать файл .clang-tidy в текущей директории. По умолчанию clang-tidy будет запускаться при открытии и сохранении файла, отображая результаты проверок clang-tidy. Можно настроить автоматическое исправление, разрешенные и запрещенные проверки и другие опции.

## Требуемые средства для запуска целей `format-labid` и `tidy-labid`
- clang-format версии >= 20
- clang-tidy версии >= 20
- python3
